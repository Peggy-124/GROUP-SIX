# 流程範例｜五關卡與六件套的完整走法

> **這是流程示範，不是任務答案。**
> 各組的題目與目標另行公告，**不要照抄這個題目**——要看的是「一趟完整流程長什麼樣」：
> 從拷問、寫 PLAN、開 TASK、記 MEMORY，到最後讓 AI 產出報告並且**抓出 AI 的錯**。

範例題目：MU（美光）、INTC（英特爾）、TXN（德州儀器）三檔近一年走勢與關稅事件日的對照。

---

## 一、先講這個範例的侷限（很重要）

**這份範例做出來的是「回顧型的結果報告」——看過去一年發生了什麼。
它跟「能拿來做決策的工具」中間，還有一段距離。**

| | 這個範例做到的 | 實際要用來輔助決策，還缺什麼 |
|---|---|---|
| 時間方向 | 回頭看已經發生的事 | 對「接下來要注意什麼」沒有著力點 |
| 事件 | 用已知的事件日對照價格 | 事件發生的當下並不知道它會不會是事件 |
| 產出 | 一份描述過去的報告 | 沒有可以持續追蹤的觀察指標或觸發條件 |
| 驗證 | 只驗證「數字有沒有抄錯」 | 沒有驗證「這個觀察在別的期間還成立嗎」 |

**為什麼還是要先做這一趟**：因為流程本身是可以帶走的。
先把「抓得到、對得齊、看得懂、跑得動、講得誠實」這五件事做熟，
之後要往前瞻或實戰應用延伸，地基才穩。
知道自己做出來的東西邊界在哪，本身就是這門課要練的能力。

## 二、五關卡實際怎麼走

| 關卡 | 這個範例怎麼做 | 產出檔案 |
|---|---|---|
| 一、抓 | 打 Yahoo chart 端點，原始 JSON **原封不動**存檔 | `raw/*.json` |
| 二、理 | UTC 秒數轉日期、濾掉 `null`、三檔取共同交易日 | （在 `monitor.py` 裡） |
| 三、看 | 起點統一為 100 再畫，標上事件日 | `chart.png` |
| 四、監控化 | 包成一支腳本，重跑就更新到最新交易日 | `monitor.py`、`summary.md` |
| 五、結論報告 | 讓 AI 讀自己的摘要，產出四節報告 | `結論報告.md` |

## 三、六件套實際怎麼用

| 檔案 | 這個範例裡它長什麼樣 |
|---|---|
| `PLAN.md` | 六節：目標、資料（含四個坑）、功能清單、驗收條件、除錯線索、維護方式 |
| `TASK.md` | 五張交辦單，**含兩次「驗收不通過」的紀錄**——這才是真實的樣子 |
| `MEMORY.md` | 每次卡關與過關的紀錄，包含 **AI 哪裡講錯、我們怎麼發現的** |
| GitHub 倉庫 | 程式、三個檔案、原始資料、圖表全部放一起 |
| 定期 commit | 每過一關存一次 |
| push | 下課前存回倉庫，並在 MEMORY 寫「明天第一步」 |

## 四、這趟跑出來的三個現象（為什麼「自己抓資料」有意義）

實際跑完之後，資料撞出三件跟直覺相反的事：

1. **2026-01-15 課 25% 關稅生效那週，美光 +22.2%、英特爾 +9.6%** —— 壞消息公布，股價反而漲。
2. **2026-07-09 美光宣布加碼投資 2500 億美元，前後五日 -17.3%** —— 利多宣布，股價反而跌。
3. **2025-08-22 政府入股英特爾 88.9 億美元，當週 -0.9% 幾乎沒動** —— 但整年漲了 317%。

這些現象**光問 AI 是問不出來的**，因為它們藏在你自己抓下來的那份資料裡。

## 五、AI 出錯的實例（範例裡刻意保留的）

第一版結論報告，AI 寫：

> 「關稅政策推升了記憶體需求，帶動美光大漲 703%。」

回頭查自己的資料才發現：**美光在六個事件日裡有三次是下跌的**，
其中自己宣布加碼投資那次還跌了 17.3%。這句因果站不住——
這一年的主因是 AI 記憶體需求，不是關稅。

我們要求它改成描述句，並在「限制與失效條件」那節寫明真正的主因。
`MEMORY.md` 與 `TASK.md` 都留著這次不通過的紀錄。

**這就是「驗收 AI 的產出」的實際樣子**：不是看它寫得順不順，
是拿它講的每個數字回頭對自己的資料。

## 六、重跑與改造

```bash
python -X utf8 monitor.py
```

換標的只要改 `monitor.py` 最上面兩行：

```python
TICKERS = {"MU": "美光", "INTC": "英特爾", "TXN": "德州儀器"}
TITLE = "記憶體與整合元件：誰接單、誰買單"
```

`events.csv` 可以自行增減事件（日期、標籤、出處三欄），圖與摘要會自動納入。
