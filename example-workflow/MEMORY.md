# MEMORY.md｜流程範例

> 每卡關或過關就記一筆。報告的「過程與困難」「解決辦法」直接從這裡抄。

## Day 1

### 09:35　拷問完成，PLAN 定案
- **做了什麼**：貼預載指令，請 AI 當面試官拷問我們的規劃。
- **卡在哪**：被問倒兩次——
  1. 「三檔要怎麼比較？」我們原本想直接畫股價，被問到才發現：
     TXN 兩百多塊、INTC 二十幾塊，畫在同一張圖上只會看到三條高低不同的線，
     完全比不出誰漲得多。改成**起點統一為 100** 才有意義。
  2. 「事件日從哪來？」原本想自己上網找，AI 追問「找到的日期有出處嗎」，
     才想起講師有發 `events.csv`，每筆都附出處，直接用比較保險也比較公平。
- **AI 哪裡講錯**：目前沒有。
- **下一步**：寫第一張 TASK，先把資料抓下來。

### 10:20　關卡一、二完成
- **做了什麼**：抓三檔 JSON 存進 `raw/`，解析成日期對收盤價。
- **卡在哪**：畫出來的線中間會斷。查了很久才發現 `close` 陣列裡有 `null`——
  Yahoo 對停牌或尚未收盤的日子會回傳 `null`，不是跳過那一天。
- **怎麼解決**：在 `to_series()` 裡加 `if c is None: continue`。
- **AI 哪裡講錯**：**AI 第一版程式碼直接用 `zip(timestamp, close)` 就開始畫**，
  沒有處理 `null`。我們把錯誤訊息連同 PLAN 第②節的坑一起貼回去，它才補上判斷。
  → 心得：坑要寫在 PLAN 裡，交辦時一起貼給它，比事後除錯快。
- **下一步**：明天畫圖標事件日。

### 11:48　收工
- 程式、PLAN、TASK、MEMORY 都 push 了，順手寫了 SETUP.md 與 HANDOFF.md。
- **明天第一步**：照 SETUP.md 重建環境，接著做關卡三（畫圖標事件日）。

## Day 2

### 09:15　關卡三完成，但圖很醜
- **做了什麼**：畫出三檔走勢，標上六個事件日。
- **卡在哪**：六條事件線的文字標籤全部擠在圖的上緣，互相重疊看不懂；
  左邊的標籤還被圖例蓋住。
- **怎麼解決**：改成圖上只標編號（紅色圓圈 1～6），完整說明放圖下方分兩行；
  圖例從左上移到左中，避開編號 1。
- **心得**：這不是程式問題是設計問題——AI 給的第一版是能跑的，但沒有人看得懂。
  「跑得動」跟「看得懂」是兩件事。

### 09:50　關卡四、五完成
- **做了什麼**：包成可重跑的腳本，重跑一次確認會更新到最新交易日；
  再把 `summary.md` 餵給 AI 產出結論報告。
- **AI 哪裡講錯**：**這次抓到一個大的**。AI 的第一版結論報告寫
  「關稅政策推升了記憶體需求，帶動美光大漲 703%」——
  我們回頭查自己的資料，**事件日前後五天，美光在六個事件裡有三次是下跌的**，
  其中美光自己宣布加碼投資 2500 億美元那次還跌了 17.3%。
  漲幅顯然不是這些事件造成的。我們要求它把因果句改成描述句，
  並補上「這一年的主要驅動力是 AI 記憶體需求，不是關稅」這個限制。
  → 這正好是四判準第②條「有沒有別的原因」。
- **下一步**：準備報告。
