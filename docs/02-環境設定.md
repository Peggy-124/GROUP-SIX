# 環境設定｜開課當天現場動手建置

> 前提：[`01-開課前準備.md`](01-開課前準備.md) 的帳號都已經辦好。
> 這一頁是課堂第一節「環境建置」時照著做的步驟，做完環境就緒，能跑出第一支程式。
>
> **這不是雜務，是正式的教學單元**：自己裝過一次 Python 與開發工具，
> 之後遇到環境問題才知道從哪裡查起。裝的時間算在課程裡，不是要壓縮的成本。

## ① 安裝 Python

1. 到 [python.org/downloads](https://www.python.org/downloads/)，下載 Windows 版安裝檔。
2. 執行安裝檔時，**務必勾選「Add python.exe to PATH」**（畫面最下方的核取方塊）——
   漏勾這一步，之後在終端機打 `python` 會找不到指令。
3. 其餘選項用預設值，按「Install Now」完成安裝。

**怎麼確認這步成功了**：開啟終端機（開始功能表打「終端機」或 `cmd`），輸入：
```
python --version
```
看到版本號（例如 `Python 3.12.4`）就代表安裝成功、PATH 也設定對了。

## ② 安裝 Antigravity

1. 到 [antigravity.google](https://antigravity.google) 下載 Windows 版安裝檔。
2. 執行安裝檔，跟著畫面指示完成安裝。
3. 開啟 Antigravity，用課前辦好的 Google 帳號登入。

**怎麼確認這步成功了**：登入後看得到 IDE 主畫面（左側檔案總管、下方終端機、
右側或內建的 AI 助手面板），代表安裝與登入都成功。

> 備援方案：若 Antigravity 當機或裝不起來，改用 [Cursor](https://cursor.com) 安裝，
> 操作方式與下面各步驟相同（都是 VS Code 系的 IDE）。

## ③ 安裝 Chrome

Antigravity 的登入與部分功能需要 Chrome 瀏覽器。

1. 到 [google.com/chrome](https://www.google.com/chrome/) 下載並安裝。

**怎麼確認這步成功了**：開啟 Chrome，能正常瀏覽網頁。

## ④ 開終端機安裝套件

1. 在 Antigravity 裡，用選單「Terminal → New Terminal」（或快速鍵）開啟內建終端機。
2. 輸入以下指令，安裝這兩天實作會用到的套件：
   ```
   pip install requests matplotlib
   ```

**怎麼確認這步成功了**：安裝過程沒有出現紅字錯誤，最後一行顯示
`Successfully installed ...`。可以再輸入 `pip list` 確認清單裡看得到
`requests` 與 `matplotlib`。

## ⑤ 在 IDE 裡 Clone GitHub 倉庫

1. 到 GitHub，右上角「+」→「New repository」，取名（例如 `tariff-semi-group3`），
   選擇 **Public**，勾選「Add a README file」，建立完成。
2. 進入倉庫頁面，點上方「Settings」→ 左側「Collaborators」→「Add people」，
   把組員的 GitHub 使用者名稱或信箱加進去；組員要**按接受邀請**才算真的加入。
3. 複製倉庫網址（綠色「Code」按鈕，複製 HTTPS 連結）。
4. 回到 Antigravity，用 Source Control 面板的「Clone Repository」（或指令面板打
   「Git: Clone」），貼上網址，選一個本機資料夾存放。

**怎麼確認這步成功了**：Antigravity 左側檔案總管看得到剛剛 clone 下來的倉庫檔案
（至少有一個 `README.md`）；請組員也各自 clone 一次，確認看得到內容、也能編輯
（不是唯讀）。

## ⑥ 跑出第一支程式，確認環境通了

1. 在 Antigravity 裡新增一個檔案 `hello.py`，內容：
   ```python
   print("環境設定完成")
   ```
2. 在終端機輸入 `python hello.py` 執行。

**怎麼確認這步成功了**：終端機印出 `環境設定完成`，代表 Python、PATH、IDE 三件事
都串起來了，可以正式開始寫程式。

## Day 1 收尾要寫的兩份檔案

下課前，除了程式與 `PLAN.md`／`TASK.md`／`MEMORY.md` 要 push 之外，
**再多寫兩份檔案，也一起存進倉庫**：

- **`SETUP.md`**：把今天①～⑥的安裝步驟，改寫成「自己組的環境重建步驟」——
  裝了什麼、版本多少、`pip install` 了哪些套件。範本見
  [`templates/SETUP.md`](../templates/SETUP.md)。
- **`HANDOFF.md`**：今天做完什麼、明天第一步、目前卡在哪、環境有什麼特別設定。
  範本見 [`templates/HANDOFF.md`](../templates/HANDOFF.md)。

**為什麼要寫這兩份**：教室電腦有還原系統，Day 2 開始前電腦會被清空——這代表
Day 2 一開場就要**照著自己昨天寫的 `SETUP.md` 重建環境**。重建順利，代表文件
寫得夠好；卡住，代表文件漏了什麼，當場補上。這就是「環境可重現」的實地演練，
也是交接能力的實測：寫給明天的自己看，看得懂嗎？

## 每過一關就 commit

**這是這兩天最重要的習慣，沒有之一。**

教室電腦有還原系統，下課會清空——存在電腦桌面或本機資料夾的東西，隔天就不見。
只有存進 GitHub 倉庫的東西才是真的屬於自己的。所以：

- 完成五關卡（抓、理、看、監控化、結論報告）**任何一關**，就用 Antigravity 左側的
  Source Control 面板存一次：填 commit 訊息 → Commit → Sync。
- 不要等到快下課才想起來存檔——commit 是遊戲裡的存檔點，越常存，風險越低。
- `PLAN.md`、`TASK.md`、`MEMORY.md` 三個檔案也是每次更新內容就存一次，
  不用等到寫完整份才存。

> 這個習慣的完整說明（為什麼、什麼時候做、下課前的收尾儀式）在
> [`03-開發流程六件套.md`](03-開發流程六件套.md)，這是本課程最重要的一份文件，
> 請務必花時間讀完。
